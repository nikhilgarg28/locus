# Locus standard library design spike

Start with **REPORT.md** and **locus/**. The primary deliverable is 13 annotated
Locus candidate source files: logical Seq/Map, law traits, permission interfaces,
two collection backends, and sharing/interior-mutability interfaces and clients.
They use `logic fn`, `Nat`, `Snap<T>`, `@(...)`, and checked runtime methods.

**These files are not a compiled or verified Locus library.** There is no Locus
compiler invocation in this bundle. Some functions have ordinary proof holes;
some internal contracts deliberately remain too weak to prove their callers;
primitive and sharing interfaces include declarations awaiting implementation.
Comments distinguish those cases. In particular, Rc/Arc/RefCell/Mutex are not
fully derived in Locus from the unique Region interface.

`src/` is a secondary, executable Rust implementation of the runtime algorithms.
Its `Observe`, `Seq`, `Map`, and `Evidence` are test instrumentation, not a Locus
Snapshot implementation, logical type, or proof kernel. Model instrumentation is
optional, but permission checks and initialization bookkeeping are not erased.
This is not a zero-cost benchmark or an expansion generated by a Locus compiler.

The design reference is nikhilgarg28/locus at
`c2818cdbe407ef49deb3301221bc29b9cba65049`. This standalone directory changes no
normative repository rule and adds no accepted trust. The snapshot-first
direction of the discussion is assumed; native storage observations and shared
protocols are explicitly identified in the report.

## Run the executable checks

With a recent stable Rust toolchain, Python 3, and rustfmt:

```sh
python3 validation/run.py
```

This runs formatting, 32 tests in each of three configurations, and nine Rust
compile-fail probes. Detailed receipts are in `validation/results.json`,
`validation/compile_results.json`, and `validation/logs/`. Expected panics are
caught by tests; they include counterexamples to deliberately invalid designs.

An additional AddressSanitizer run passed on x86_64 Linux:

```sh
RUSTC_BOOTSTRAP=1 RUSTFLAGS='-Zsanitizer=address' \
  CARGO_TARGET_DIR=/tmp/locus-stdlib-asan \
  cargo test --offline --target x86_64-unknown-linux-gnu
```

That command requires a Rust installation with the sanitizer runtime. It is
instrumentation, not the Locus toolchain. No Miri, Lean, or clippy result is
claimed. The environment's clippy command was unavailable.

## Source map

| Locus source | Scope |
|---|---|
| `00-seq.lc` | Inductive logical sequences and recursive lemma candidates |
| `01-map.lc` | Finite function-backed logical maps and finite-support proofs |
| `02-laws.lc` | One key projection shared by equality, order, and hashing |
| `03-permissions.lc` | Assumed memory-core contracts and initialized ownership |
| `04-std-api.lc` | Native observation proposal and sealed bridge certificates |
| `05-native-vec.lc` | Permission-backed vector operations and invariant gate |
| `06-wrapped-vec.lc` | Std vector plus erased logical contents |
| `08-boxes.lc` | Owned-pointer Box and std Box wrapper |
| `09-btree-algorithm.lc` | B-tree search, split, merge, rotations, insert, remove |
| `10-hash-algorithm.lc` | Linear probing, tombstones, growth, map invariant |
| `11-wrapped-maps.lc` | Std BTreeMap/HashMap plus logical map contents |
| `12-interior-and-sharing.lc` | Certified Cell values and explicit protocol gates |
| `13-interop-programs.lc` | Proof-bearing clients and Rust handoff examples |

The numbering has no file 07 because the initial map sketch was replaced by the
two algorithm files. Every source is included in the report's source appendix.

The runtime collection modules forbid unsafe code; memory primitives and
sharing/interior modules contain the explicitly separate unsafe algorithms.
Native B-tree nodes and hash/vector payloads use the custom permission storage.
Allocation, initialization metadata, and shared control blocks still use Rust
facilities. This is not a no_std library or a replacement allocator.
