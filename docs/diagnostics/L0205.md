L0205: Integer literal outside its type range

The integer literal parses, but its mathematical value does not fit the expected machine type. Choose an appropriate wider type or a value in range. Logical Int literals do not acquire machine overflow behavior merely because a similar runtime literal does.

Example from `tests/corpus/reject/literal_misfit.lc`; the full file is a regression test.

```rust
// These literals lex and parse. A suffix names the literal's type, which
// then has to be the type expected; a literal without one takes the type
// expected of it and must fit it; a string is only the message of a
// built-in form, which does not exist yet.
fn wide() -> u8 {
    1u16
}

fn signed() -> u8 {
    0x7F_i8
}

fn past() -> u8 {
    0x100
}

fn past_with_suffix() -> u8 {
    256u8
}

fn huge() -> u8 {
    340282366920938463463374607431768211456
}

fn text() -> u8 {
    "a\tmessage"
}
```
