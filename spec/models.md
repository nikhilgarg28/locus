# Snapshots and models

Logical code sees a runtime value in two ways: as what it is, its *snapshot*, and as what it means, its *model*. The language supplies the snapshot of every type that it can see, and no program writes or replaces one. Every type that has a snapshot has a model: the snapshot itself, unless one is declared with `impl Model for T` or derived with `#[derive(Model)]` where the type is declared, or declared by Locus's library, for a type of the standard library or for a type of its own. [RFC 0002](../design/rfcs/0002-logical-layer.md) explains the design.

Logical code reaches runtime data only through places: locals, fields, and the targets of references and `Box`. A place that logical code reads is *captured*: it stands for the model of the place's snapshot. `snap(x)` gives `x`'s snapshot, of type `Snap<T>`, and applies no model.

## Snapshots

r[models.snapshots]
Every runtime type `T` that Locus can see ([`models.snapshots.seen`](#snapshots)) has a snapshot type `Snap<T>`, which holds what a value of `T` is. Every value of `T` has a snapshot of that type, and the type may hold values that no value of `T` has ([`models.valid`](#valid-snapshots)). For a struct or enum it has the same fields and variants, each of its field type's snapshot type, proof fields included. A machine integer's snapshot is an integer, a `Nat` for an unsigned type and an `Int` for a signed one, and a `bool`'s a `Bool`: there is no logical integer type of a fixed width. `Box` and references are transparent: `Snap<&T>` is `Snap<T>`. The snapshots of arrays and slices are `Seq<Snap<T>>`. A collection of Locus's library, such as its `Vec<T>`, is a struct, and its snapshot is that struct's, with the elements' snapshots in a logical field ([`collections.contents`](collections.md#contents)). A snapshot never depends on a model: a type's snapshot holds each field's snapshot, whatever model the field's type has. So that every snapshot is finite, a field is *cut* when its type reaches the type that declares the field again through a reference, following type arguments, and a cut field's snapshot follows no reference: each reference in it holds only its address. The cut belongs to the type that closes the cycle, so a generic type's snapshot has the same shape for every type argument. A cut field's snapshot has a type of its own (`models.snapshots.cut`).

r[models.snapshots.cut]
A cut field has, in its owner's snapshot, the type `CutSnap<F>` for its declared type `F`: the snapshot of `F` with every reference in it held as its address. `CutSnap<F>` is defined for every type that holds no proof field which reads through a reference, has no model, and is not `Snap<F>`: a value of one is not accepted where the other is required. A model or a logic function takes a snapshot and no place ([`logic.fn.parameters`](logical-layer.md#logical-code)), so it reads nothing behind such an address. A function body may read the place behind one, as it reads any place: the read gives the value name of that place's current version, and two reads with no write between give the same name. A type that holds a proof field which reads through a reference, at any depth and at the type arguments in use, has no `CutSnap`: the proof field's proposition would speak of a referent that the cut snapshot does not hold. Such a type is legal, and has its ordinary snapshot, wherever it is not in a cut field. A type that would hold it in a cut field is rejected, and so is a use of `CutSnap` at it. This is a rejection and not an opaque snapshot: a proof field cannot be opaque about what it proves.

r[models.snapshots.seen]
A type has a snapshot, and so a model, only where Locus can see what it is. The language gives one to the machine integers, `bool`, `()`, references, `Box`, tuples, arrays, slices, and raw pointers. Locus gives one to each struct, enum, and union that it lowers: one declared in a `.lc` file or in a `locus!` block. Locus's library declares one for types of the standard library, among them `Option`, `Result`, and the types with interior mutability. It declares none for a collection of the standard library: the standard library's `Vec` has neither a snapshot nor a model, and the `Vec` that logical code reads is the one of Locus's library, a struct that Locus lowers ([`collections.contents`](collections.md#contents)). A type parameter, or an associated type of one, has one where the program writes the bound ([`models.capture.bound`](#models)), and a struct or enum has one where each field's type has one or the field is marked `#[opaque]` ([`models.snapshots.opaque`](#snapshots)), at the type arguments at which that holds. Where that would need the type's own snapshot through an associated type, as for `Node<K>` whose field has the type `K::Out` when that is `&Node<K>`, the type has none. Any other type has neither a snapshot nor a model: a closure, a function item, a function pointer, a trait object, a type that an `impl Trait` hides, a type of a crate that Locus does not lower for which its library declares nothing, and a struct or an enum with a field of such a type and no mark. A place of such a type cannot be captured, `snap` cannot be applied to it, and `Snap<T>` cannot be written of it.

r[models.snapshots.opaque]
A field whose type has no snapshot ([`models.snapshots.seen`](#snapshots)) is marked `#[opaque]`. Its snapshot is then *opaque*: an unknown value, of a type of its own for each field type, which logical code can hold, pass on, and compare, which a move or a copy keeps, and which nothing looks into. The mark changes the field's snapshot and not its type: the field read as a place still cannot be captured, and its opaque value is reached through the snapshot of the value that holds it, as `snap(s).f`. A struct or an enum that Locus lowers and that has such a field with no mark is not rejected: it is declared, built, and used in runtime code as it is in Rust. It has no snapshot and no model. So a place of it cannot be captured, `snap` cannot be applied to it, `Snap<T>` cannot be written of it, a model cannot be declared or derived for it, and it is not accepted where a `Model` bound is asked for. Each of those is an error, which names the field's type and says to mark the field `#[opaque]`. A field whose type names a type parameter, or an associated type of one, needs no mark. A union's snapshot is opaque as a whole, so its fields need none either, and the snapshot of a type with interior mutability holds nothing of its contents ([`models.frozen-data`](#snapshots)).

r[models.snapshot-privacy]
A snapshot holds every field of its value, private ones included, but logical code reads a field of a snapshot only where Rust code could read that field.

r[models.frozen-data]
A snapshot holds nothing that can change without a write that Locus sees: not the contents of an `UnsafeCell`, which are opaque, and not the target of a raw pointer, only its address. A model, being a function of the snapshot, reads neither.

## Valid snapshots

r[models.valid]
For each type `T` that has a snapshot, the language defines a proposition on its snapshots, `T::valid(s)`, from the type's structure, and no program declares or changes it. A machine integer's snapshot is valid when it lies in the type's range, which for `usize` and `isize` is that of the configuration being checked: `u8::valid(n)` is `n <= 255`. The snapshot of a reference or a `Box` is valid when its target's is. That of a tuple, a struct, or an enum is valid when every field's is, for an enum the fields of the variant it is. That of an array `[T; N]` is valid when its length is `N` and every element's is valid. That of a slice, of an `Option`, of a `Result`, and of a collection of Locus's library is valid when every element's or payload's is. A `bool`'s, a raw pointer's, an opaque part, a cut field, a proof field, and a logical value are always valid.

r[models.valid.captured]
The snapshot of a runtime place is valid: where logical code captures a place `x` of type `T`, or writes `snap(x)`, `T::valid(snap(x))` holds, and proofs may use it. So a value captured from a place of type `u8` is at most 255, and the captured length of a `[u8; 4]` is 4. It reaches the fields of a captured struct, since a field of a snapshot is the snapshot of that field.

r[models.valid.not-assumed]
Nothing is assumed valid that no runtime place gave. A value of type `Snap<T>` that is a parameter of a logic function, that a `forall` or an `exists` binds, or that logical code computes may be one that no value of `T` has: a `Snap<u8>` is any `Nat`. A logic function that needs a snapshot to be valid takes a proof of it, as in `fits: @u8::valid(n)`.

## Models

r[models.observation]
A runtime place that logical code reads is *captured*: it stands for the model of the place's snapshot. That holds wherever the place is read: as an operand, on either side of `===`, as the receiver of a method call, and as an argument, whatever the type of the parameter. Fields are selected on the place first, so `p.x` is the capture of the field `x`. `snap(x)` is the snapshot of the place `x`, with no model applied, and is how a snapshot is given to a parameter of type `Snap<T>`. `model(x)` is the capture of the place `x`, written out; to a snapshot value `s`, a type's model is applied by the type's path, as `T::model(s)`, and `model(s)` is rejected, since a snapshot's type does not say which type it is a snapshot of. The model of an unsigned integer is a `Nat`, and that of a signed integer an `Int`, so arithmetic on them in logical code never overflows.

r[models.default]
Every type that has a snapshot has a model. It is the type's snapshot, unless a model is declared for the type, derived for it, or declared for it by Locus's library. So a value of a type with no declared model is used in logical code as its snapshot is, and `p === q` is then the equality of the two snapshots.

r[models.by-parts]
A type that the language or Locus's library builds from other types is modeled part by part: the model of `&T`, `&mut T`, and `Box<T>` is `T`'s; the model of a tuple is the tuple of its components' models; that of an array or a slice is a `Seq` of its elements' models; that of an `Option` is a `Maybe` of its payload's; and that of a `Vec` of Locus's library is a `Seq` of its elements' models ([`collections.model`](collections.md#contents)). A struct or an enum that a program declares is modeled as its declaration says, and by default as its snapshot, which holds its fields' snapshots and not their models.

r[models.capture.fields]
For a place `o` whose type has no declared model, and a field `f` of it whose type has one, the two orders differ: `o.f` read as a place is the field's model, and the field `f` of the capture of `o`, as in `whole.f` after `let whole = logic! { o };`, is the field's snapshot. Where the field's model has another type than its snapshot, using one where the other is meant is a type error. Where a declared model has the snapshot's own type, both have that type and nothing is reported, though they are two values wherever the model changes one.

r[models.capture.methods]
A method call on a runtime place in logical code captures the place and resolves on the type of the captured value. Nothing else is tried: not a logic function that the runtime type declares, and not one of its snapshot's type when its model is another type. A logic function that a type declares over its snapshot is called by its path, on the snapshot: `Stack::room(snap(s))`.

r[models.capture.bound]
A value whose type is a type parameter `T`, or an associated type of one such as `F::Out`, is captured, and its snapshot taken, only where a `Model` bound on that type is in scope, written by the program on the function, on the `impl`, or on the type's declaration. No bound is implied, and none is inferred from a use. Under the bound, `Snap<T>` and the model's type `T::Logic` are the same types in generic code as at each instantiation. A proposition in the type of a field that reads a field whose type names `T` needs the bound on the type's declaration. Where the bound cannot be written, as on the type parameter of a method of a trait that another crate declares, the value cannot be captured. A type with no model ([`models.snapshots.seen`](#snapshots)) is not accepted as a type argument where the bound is asked for.

r[models.total]
A declared model is a logic function of one parameter, its type's snapshot, and takes no proof. It is defined for every value of `Snap<T>`, including those that no value of `T` has ([`models.valid.not-assumed`](#valid-snapshots)).

r[models.one-per-type]
A type that has a snapshot has exactly one model, the same wherever the type is read: in the module that declares it, in another module or crate, and in generic code under a bound. A model is declared for a type as it is declared, at all its type arguments: one declared for some of a generic type's arguments only is rejected, since generic code would read the others through the default. Two declarations of a model for one type are rejected.

r[models.derived]
`#[derive(Model)]` on a struct or enum that its crate defines, with no type parameters, gives it a model with the same fields and variants, each field taken to its own model, and its bare proof fields, whose type is a proof type, left out. A field that holds a proof inside a runtime type, such as `Option<@P>` or `Vec<(usize, @(i < n))>`, keeps its runtime structure, taken to that type's model. It is rejected unless every field's type has a model, which the type of a field marked `#[opaque]` does not, and rejected when the type reaches itself through a reference, following type arguments: the field that closes the cycle is cut in the snapshot and has no model, and the model type could have no values. A type that reaches itself only through `Box` may derive its model, whose type is then recursive. Two values have equal derived models exactly when they are the same variant and their fields' models are equal.

r[models.bounds-on-functions]
A `Model` bound appears on the type parameters of a function, of an `impl`, and of a struct or an enum, and never on a trait. When a crate is exported it appears only on a function's type parameters: an exported program has no `Model`, and removing the bound from an `impl` could change which implementation a call selects.

r[models.declared-by-owner]
A type's model is declared, or derived, with the type: in the `locus!` block, or in the `.lc` file, that declares the type. So a crate declares no model for a type of another crate. For the standard library's types, Locus's library declares it.

r[models.own-definition]
A model's definition never depends on the model itself, directly or through other types' models: inside a declared model, and inside every logic function it calls, the snapshot is read through its fields and the model being defined is never applied, and the models that derived and declared models use form no cycle.
